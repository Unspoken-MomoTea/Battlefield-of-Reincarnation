# 世界引擎 V2 · P2 模块化设计

## 目标

P2 只解决 `script/世界推进系统.js` 单文件过大带来的维护风险，不改变世界变量、Prompt、WorldResult Schema、生命周期、API 行为或 Shadow DOM UI 语义。

## 部署不变量

- 酒馆继续只加载 `script/世界推进系统.js`，现有安装方式不变。
- 不在运行时使用 `import` / `export`，不要求酒馆额外加载多个文件。
- 不新增 npm / package.json 依赖；仓库当前没有 npm 构建链，不为单一拼接任务引入第二套包管理。
- `script/世界推进系统.js` 变为可直接导入的生成交付文件；开发时编辑 `script/world-engine-src/*.part.js`。
- `tools/build-world-engine.py` 只按固定顺序拼接源码片段，不改写代码、不压缩、不注入业务内容。
- 构建检查必须保证源码片段拼接结果与交付文件完全一致，防止出现“双源真相”。

## 源码边界

按当前依赖顺序采用连续片段，避免为了“模块漂亮”重新排序大量函数：

| 顺序 | 文件 | 职责 |
|---|---|---|
| 00 | `00-foundation-prompt.part.js` | IIFE 开头、基础工具、token 观测、主题常量、正文清洗、时间基础、默认 Prompt 与预设编辑辅助 |
| 10 | `10-world-state.part.js` | 后台记录定义、世界现场、事件生命周期、因果/时间修复、热人物/异端、patch 安全与归一基础 |
| 20 | `20-world-result.part.js` | WorldResult Schema、关系组件 Schema、结果归一/合并/分片、Compiler、状态校验、patch 应用与回复解析 |
| 30 | `30-context-protocol.part.js` | 世界书激活、NPC 构筑审计、正文只读投影、世界上下文、输出协议与审计规则 |
| 40 | `40-engine-runtime.part.js` | `SamsaraWorldEngine` 的配置、专属 API、Prompt 文档、世界书读取、请求构建、调度、运行与检查状态 |
| 50 | `50-engine-ui.part.js` | 世界推进 Shadow DOM 面板、六主题 CSS、交互事件和全部页面渲染 |
| 60 | `60-bootstrap.part.js` | CommonJS 测试导出、酒馆沙箱 runtime 适配、实例化与卸载 |

这些是“同一 IIFE 的构建片段”，不是独立运行模块。片段可以共享词法作用域；只有最终拼接文件需要单独通过 JavaScript 语法检查。

## 单一来源规则

1. 业务源码只修改 `script/world-engine-src/*.part.js`。
2. 修改后运行 `python tools/build-world-engine.py` 生成 `script/世界推进系统.js`。
3. `python tools/build-world-engine.py --check` 必须在 CI / 验收中通过。
4. 永久测试检查模块顺序、职责锚点、IIFE/测试导出/启动尾部，以及“源码拼接 = 交付文件”。
5. 不在构建脚本里复制 Prompt、Schema、CSS、变量定义等业务文本；构建脚本只维护文件顺序。
