# 当前版生命周期审查

本次是代码审查与合成存档测试，未连接真实酒馆 API，未写入用户存档。

## 已完成的界面与隔离修改

- “任务与事件”改为“世界事件”，移除任务、成就、任务统计及任务摘要。
- 保留原系统的任务和成就变量，不删除存档数据。
- 清除发给后台的旧事件关联任务字段，WorldResult Schema 不再声明该字段。
- 旧 JSON Patch 兼容回复中的任务修改也被过滤，避免绕过 WorldResult 的职责边界。
- 当前变量投影不含任务树，但正文楼层仍是 AI 消息原文：若其中包含任务播报或变量块，文本仍可能带相关信息，不能理解为全文中保证没有任务信息。

## 已验证的正常路径

| 场景 | 当前行为 |
| --- | --- |
| 主神空间内 | 世界名或空间标识命中时阻止后台推演 |
| 正常完整副本结算 | 结算程序先取消后台请求；清空世界后台，并设置返回主神空间 |
| 结算后进入新副本 | 沿用已清空后台，MVU 更新后可重新初始化；仍要求世界名和空间标识正确 |
| 单一世界阶段结算 | 保留后台，不当作离开该世界；结算消息不推进，下一个正文楼层恢复 |
| 切聊天、切候选回复、删消息 | 取消请求；回包前检查上下文及世界时间，旧结果不能写入新上下文 |
| 推进成功 | 最近变化最多100项且仅本轮；运行记录最多20项 |

## 已复现、尚未修改的缺口

### 中优先级：人物/地区明细仍缺独立长期压缩

事件生命周期已经会清理冷事件引用，但人物行程、认知来源、地区近期变化等明细本身仍没有独立的长期压缩/归档策略。长期单一世界仍可能在这些明细层累积数据，不能声称所有后台明细都已经具备完整生命周期。

### 中优先级：跨副本隔离依赖正常结算清理

直接把世界名称换到副本B而保留副本A后台时，旧世界人物仍进入B的投影。
后台没有独立副本实例标识，也没有针对这种换世界的兜底隔离。
正常完整结算路径通过；跳过结算、异常切换、旧档残留路径不完善。相同世界二次进入尤其不能只用名称区分。

### 已修复：数字日期跨月时间差

worldDateKey 对可识别的数字年月日改用真实公历日期序号计算，不再把每个月近似为31天。合成案例 2026-02-28 上午 → 2026-03-01 上午现在为24小时；十二时辰与刻数继续叠加到当天时刻。无法解析成数字年月日的作品内相对时间仍交给语义复核，不强行换算。

### 已修复：冷事件引用阻塞归档

结束超过保留窗口的事件进入冷区时，程序会先清理人物、势力地区、传播中的旧关联事件；同样已经结束并进入冷区的事件之间也会退休旧前因。仍在进行/待发生的活跃事件如果依赖该前因，则继续保留引用。当前因果故事线上的宏观节点受保护，不会被普通冷归档拆掉。

针对旧版漏改状态的局部活动，当前事件超过约7个世界日、近期节点超过约30个世界日仍为“进行中”会被列入强制复核；本轮确认其早已完成/取消后，在无活跃后续依赖时立即压成历史，不再被旧人物关联永久卡住。

### 已修复：切聊天后请求检查保留旧资料

CHAT_CHANGED / MESSAGE_SWIPED / MESSAGE_DELETED 现在会在 cancel 后调用 resetInspection，清除 lastRequest、previewRequest、lastReply、lastWorldResult、编译结果、失败记录和重试计数。请求检查不再跨聊天/存档显示上一上下文资料，也不会把旧纠错内容误认为本档实际发送。

## 其他代码审查风险

- 同楼层宏观修复可以再次提交，但独立提交标记仍复用楼层 fingerprint。辅助计算脚本依赖标记前后不同来跳过冷却/状态扣减，二次提交存在被当作普通更新处理的风险。建议分离楼层去重标识和每次提交标识，再做集成复现。
- 历史最多200条，送模型最近24条；因果偏移只投影最近8条并保留累计值。历史超过200条会移除最旧记录，并非永久冷存档，长期关键事实需要单独保留策略。
- 活跃传播仅投影最近24条，持久记录到期或明确结束才回收；长期不结束的旧传播可能被投影窗口挤出但仍占用引用。

## 复现方式

- node tests/world-engine.cjs：核心回归包含生命周期、时间一致性、WorldResult 与正文承接链路。
- node tests/world-engine-ui.cjs：覆盖世界事件页、日历、窄屏及请求预览交互。
- node tests/world-engine-lifecycle-audit.cjs：继续作为只读诊断脚本，用于观察跨月时间、冷事件归档、跨副本残留与切聊天检查缓存。
