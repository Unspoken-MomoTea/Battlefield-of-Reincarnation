# 世界推进 Prompt Registry

`WorldPromptRegistry` 是世界推进所有**静态 AI 指令文本**的唯一编辑入口。提示词预设页的“全部实际提示词”直接读取这个注册表，不再依赖人工记住某个 `59-*.part.js` 里还藏着什么字符串。

## 收录范围

注册表覆盖四种发送位置：

1. **system**：主预设、核心边界、宏观骨架、世界自救、NPC 审计、WorldResult 协议、任务/时间轴/维护/探索/因果/时间/传闻/世界活动等运行模块。
2. **user payload**：输入语义、宏观骨架规划与验收、正文投影说明、到期事件复核、时间线基准、异端复核、世界活动硬要求等。
3. **辅助模型**：长期历史压缩 system 与输入说明。
4. **纠错重试**：已有部分结果+补充清单、已有部分结果、首次整体纠错三种要求。

任务只读语义、未命中时间轴资料时的保守说明、传闻世界侧取材边界也属于实际发送给模型的静态指令，现已分别以 `inputSemantics / chronologyNoEvidenceGuidance / rumorSourceBoundary` 登记，不能再藏在请求构造文件里。

每项必须包含 `key / title / group / source / scope / condition / defaultValue`，UI 必须展示“作用范围”和“发送条件”。

## 不属于可编辑 Prompt 的内容

以下保持程序契约，不开放为提示词：

- JSON Schema 与字段白名单；
- MVU 允许写入路径；
- 因果引用、时间比较、生命周期回收等校验算法；
- 根据当前错误动态生成的具体错误事实、实体名称和计数；
- 当前世界变量、世界书正文和聊天正文等运行时资料。

这些内容可能会出现在请求中，但它们是数据或程序诊断，不是隐藏的静态提示词。

## 新增规则

以后任何新的静态 AI 指令必须先登记 `WorldPromptRegistry`，再由业务层引用。新增后需要同时满足：

- 提示词预设页可见；
- 可进入编辑模式；
- 保存/导入/导出预设可持久化；
- 请求检查能看到注册表清单；
- 测试覆盖发送条件与实际替换结果。

不要再把新的不可编辑指令直接拼接到 `request.system` 或请求 JSON。
