# 世界引擎接入

把 `世界推进系统.js` 作为独立酒馆脚本加载，并更新 `悬浮球状态栏.js`、`ZOD脚本.js`、`辅助计算脚本.js`、结算任务美化，以及世界书的 `[variables]当前变量`、`[mvu_update]变量更新规则` 两个条目。没有构建产物自动发布步骤；本目录源码不会自动同步到已导入酒馆的角色卡。

终端设置新增「世界推进」总开关，作为独立世界引擎的唯一用户开关。关闭时点击左侧「世界」仍显示原来的 `renderWorldTab` 世界面板，正文/MVU继续使用旧世界推演规则；开启时点击「世界」进入独立世界引擎面板，返回或按 Esc 恢复终端。独立脚本未加载时总开关无法启用，但旧世界面板仍可正常使用。

开启「世界推进」会自动把终端「额外模型配置」的 enabled 打开，并与商城刷新、血统融合共用所选连接；关闭世界推进只停止世界引擎，不会反向关闭额外 API，以免影响其他功能。总开关已开启但 API 地址或模型尚未准备好时，`isEnabled()` 返回 false：世界引擎面板显示等待配置，自动推进暂停，同时 EJS 恢复旧因果轨道、传闻与正文世界推演，避免出现两套系统都不工作的空档。每个正文楼层的 MVU 更新完成后，仅在总开关开启且额外模型 Ready 时执行一次联合请求。每次消耗副 API 额度，120 秒超时；失败保留旧状态，可手动重试。不自动付费重试。

## 当前实现

界面第二版采用世界档案布局，不再显示 JSON。世界推进页包含副本日期、累计游玩天数、活跃事件、未来节点、人物动态、近期变化和任务进展。月历以当前副本年月为锚，按公历展示；可切月、点击有事件的日期筛选时间线，操作不会修改世界时间。事件可按状态或关键词筛选。

人物档案保留行动起止时间、行程、认知来源和登场条件；旧存档中的承诺、待决事项、关系变化字段继续兼容，但当前没有独立调度逻辑，因此不再展示，也不要求模型生成。势力地区继续维护控制权、资源、内部派系及近期变化。任务不再维护第二套“剧本/阶段”树，而是直接通过事件的关联任务与实际任务状态联动。`最近变化`只保存本轮成功提交产生的新变化，跨轮记录由运行记录与历史锚点承担。

`node tests/world-engine-ui.cjs` 使用虚构灰港数据运行本地无头 Edge，检查桌面/手机、日期筛选、人物明细、标签页、空状态及返回行为。截图位于 `tests/artifacts`，只用于验收，不会将示例剧情写入角色卡。

- 世界推进、因果轨道、角色、势力地区、任务联动与信息传播共用一次请求和一个快照，结果包含 JSON Patch 增量操作。
- `世界.后台` 的调度核心是事件、人物行动、势力地区、历史与传播；`剧本`仅为旧存档兼容字段，新推演不再写入或依赖。另存最后处理标识与最近20轮运行说明。
- 事件前因及关联对象必须存在，因果链不允许循环。批次任意错误均拒绝整次写入。
- 兼容投影更新因果轨道、势力、探索、异端名单、传闻；人物只改已有好感，任务和成就只改已有状态。人物属性、奖励、主神任务创建仍由原系统负责。新的剧情任务计划放后台剧本，不能直接发放主神奖励。
- 世界推进实际启用时，原模型只处理当前场景事实；后台补场外演进并接管副本初始化后的因果轨道与场外传闻。正文读取公开摘要与因果轨道。副 API 返回后只要聊天、副本和世界时间锚点没有变化，就把世界补丁重基到最新 MVU，保留 HP 等无关并发更新；推进锚点变化才丢弃旧结果。
- 后台提交携带楼层标记，辅助脚本只重算稳定值，不额外推进战斗轮次或扣减状态持续时间。稳定值也在写入前按既有公式计算。
- 正文通过当前变量条目只读公开摘要；后台管理界面明确包含隐藏计划和真相。首版为正文后推演，下一次正文通过当前变量读取结果；没有新增阻塞正文的前置副 API 调用。
- 世界书默认读取绑定主书、附加书的启用条目，可在提示词预设页加载目录并逐条勾选；普通禁用条目可在强制模式显式纳入。`[variables]`、`[mvu_update]`、正文额外思考、选择世界/主神任务/试炼/结算等技术条目始终隔离，避免把MVU和正文协议重复塞给世界引擎。正文读取最近 1—100 层，默认 6 层，包含用户和 AI。动态条目仍经 EJS 求值；不自动读未绑定书及全局书。请求总字符超过 24 万会报错，不静默截断。
- 副本时间由正文/MVU原流程维护，后台不改两套时间。普通副本完整结算清空后台；单一世界结算保留。结算楼层不推演，下一个普通正文楼层可继续。
- 切聊天、swipe、删楼取消请求；MVU 楼层快照保存状态。历史面板不触发当前副本清理。进主神空间后停止副本推演。

## 模型补丁容错

世界模型返回的是增量事实，不再要求新建后台记录时一次写齐所有模板字段。对 `/世界/后台/{事件|人物|势力地区|历史|传播}/{名称}` 的整记录补丁，引擎会先用当前模板补缺省字段，再与已有记录合并；因此遗漏 `公开动态`、`关联事件`、`目标` 等空字段不会导致整轮失败。未知顶层字段会被丢弃，可选明细数组（如行程单条记录）的内部结构仍严格校验。

旧存档中的半截后台记录也会在每次事务开始时按当前模板自愈。模型若误写 `/系统状态/待播报记录`、后台运行记录/最近变化/处理标识或旧后台剧本，这些程序自管路径会被忽略而不是让整轮回滚；玩家属性、货币、奖励、世界时间等危险越权路径仍然硬拒绝。

显式旧故事线导入的主线节点现在只作为安全骨架写入，不再要求所有导入节点在同一轮补齐时间与条件。后续滚动时间轴会逐步排程，因此不会再出现“主线节点尚未排程”导致整轮无法落盘。

## 因果轨道、EJS职责切换与提示词结构

世界引擎开启时，后台事件图负责场外世界运行，`世界.因果轨道`只作为3~5个宏观节点的投影。若故事线只有一句概括、少于3个节点或超过5个节点，引擎会优先要求模型修复；若模型漏写而现有事件已足够，引擎会按已有事件和世界时间自动补成3~5节点，不凭空制造新事件。玩家或其他人物只有在实质改变关键人物命运、重大事件、势力格局或主线可行性时才新增偏移记录；偏移导致旧主线不可继续时，同步重构故事线与下一节点。世界超稳仍禁止新增偏移。

`[mvu_update]变量更新规则` 与 `⚙️额外思考` 不再永久删除原有世界推演能力，而是通过 EJS 检测 `Samsara.worldEngine.isEnabled()`：世界引擎开启时隐藏普通MVU的因果轨道、场外传闻及正文场外推演职责；关闭时恢复原有因果轨道、传闻和 Step.5 世界推演提示。因此关闭独立引擎后，原流程仍可独立工作。

分段提示词中的结构标题由界面固定保存，textarea 只编辑正文；`【世界推进】`、`【世界演进准则】`、`【因果轨道与偏移】`、`【角色管理】`、`【势力与地区】`、`【任务联动】`、`【信息传播】` 等缺失标题会从默认预设自动补回。旧 localStorage 预设会迁移补上新分段，不会因为用户曾保存旧版预设而缺失新的世界演进规则。除此之外，核心世界约束还会独立注入请求，因此即使分段正文被清空，也不会破坏事件调度、因果轨道和偏移记录的基本协议。

## 运行时容错与并发重基

世界模型可把首次设置写成 `replace`。对于后台事件/人物/势力地区/传播的合法记录和明细字段，目标尚不存在时按安全 upsert 处理；例如 `/世界/后台/事件/校医室聚集/开始时间` 会先建立事件骨架，再写入开始时间。人物稳定名会与后台人物、关系列表和异端雷达做标点归一匹配，因此 `张彪~1狂暴分支` 可自动落到已有的 `张彪·狂暴分支`，避免因斜杠/中点差异创建重复人物。

副 API 请求期间若辅助脚本或其他 MVU 逻辑只改变不相干字段，世界引擎会把补丁重基到最新变量后再提交，不再因为完整 stat_data 不同而整轮失败。只有聊天楼层、世界名称、世界时间或主神空间状态等推进锚点发生变化时才拒绝旧回复。危险越权路径、奖励、货币、玩家属性等安全边界仍保持硬拒绝。

## 分层时间轴与归档

世界推进不再把日历当成单纯展示。每次请求都会生成“时间线调度”信息，以 `世界.时间` 为唯一锚点，判断是否缺少时间轴、是否需要补充远期宏观节点、哪些宏观节点已经接近当前时间需要展开，以及哪些非公历/作品内纪年事件需要模型按世界书语义复核。

事件按三种尺度组织：当前活动层用于数小时到约两天内的精确节点；近期规划层用于数天到数周的重要人物、势力与局部事件；宏观锚点层用于更远的战争、政权、灾难与原著关键节点。紧凑副本可按小时或“第X夜”推进，大型长期世界只保存必要宏观节点，随着时间接近再滚动展开，避免一次生成多年琐碎日程。

`后台.事件` 维持约 180 条调度目标。超过目标时，引擎会从无其他记录引用的“已完成/已取消”事件开始压缩为历史锚点并回收详细事件；历史锚点再保持约 200 条上限。模型本身仍不能直接删除普通事件或改写历史，清理由引擎在事务内完成。这样长期副本不会把全部旧事件永久带进每次请求。

## 公共接口

### 本轮界面与调度更新

2026-09-08 写入与资料界面修复：

- 对象字段的 add 采用 JSON Patch 设置语义，允许更新已存在的公开摘要。历史依然不可覆盖；时间、奖励与数值边界保护不变。
- 返回解析接受标签、JSON 代码块及完整 JSON 外的说明文字，不猜测修复破损 JSON。原始模型回复和错误保留在请求检查中（当前页面内存）。
- 世界页只保留人物动态、近期变化、活跃事件及任务进展；完整日历默认折叠。角色页移除没有独立功能的承诺、抉择、交际圈占位以及异端档案，不删除旧存档中的兼容数据。任务页改为“任务与事件”，不再显示剧本与阶段。
- 世界书增加“遵循蓝绿灯 / 强制读取勾选项”：前者蓝灯常驻，绿灯根据所选正文窗口匹配主关键词和次要条件；后者可显式纳入禁用项。不修改酒馆世界书自身设置。目录灯色标记激活类型，命中清单记录实际读取或跳过原因。
- 请求检查默认仅展示数量，清单和 system/user 分段阅读均折叠；完整原文单独保留，长内容在固定高度内滚动。user 原文发送时也有 JSON 缩进，分段阅读按世界书、变量、正文楼层、到期事件展开。

面板采用 Shadow DOM 隔离宿主全局样式，并明确使用视口高度。测试覆盖 320px 窄屏、240px 短屏和宿主强制隐藏 main/section 的干扰样式。世界页增加活跃事件、任务摘要和跳转；人物页增加名册选择；势力页改为地区/热点/势力关系名录、势力档案与各地情势。

预设按模块拆开编辑，保存后按顺序拼接。请求检查展示“最近实际发送”与“下一次请求预览”的完整 system/user 原文，以及具体世界书条目和楼层清单。预览不调用 API；实际发送记录仅保存在当前页面内存，刷新后不保留。

显式用箭头或换行分隔的旧故事线可导入为主线事件，不猜测自然语言段落、不伪造日期。导入节点先作为安全骨架提交，不再要求同一轮全部排程；后续由滚动时间轴补时间、条件与默认走向。已有到期事件若保持待发生，必须注明本轮更新时间、阻碍条件和下次检查，否则不写入。当前仍由副 API 核验条件与执行事件，不是脱离模型的完整确定性调度器。

父窗口 `Samsara.worldEngine` 提供 `open()`、`close()`、`toggle()`、`isOpen()`、`run()`、`cancel()`、`getState()`、`isConfigured()`、`isAvailable()`、`isEnabled()`、`setEnabled(boolean)`、`setPreset(text)`、`dispose()`；类为 `Samsara.WorldEngine`。其中 `isConfigured()` 只表示用户总开关，`isAvailable()` 表示额外模型当前可用，`isEnabled()` 同时要求两者为真，EJS与自动调度统一使用 `isEnabled()`。

`run()` 不推进时钟，不重复执行已成功处理的同一楼层。默认运行失败不会落入聊天变量，可在面板底部看错误；成功摘要写入楼层后台。世界引擎面板不再拥有第二个「自动」开关，所有自动运行行为由终端设置中的「世界推进」总开关控制。`dispose()` 取消请求并移除界面和事件监听。
