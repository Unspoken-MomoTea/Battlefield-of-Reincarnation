# 世界引擎 V2 审计与实施矩阵

审计日期：2026-09-10

参考对象：`Draw on/世界引擎`

目标：保留轮回战场现有 MVU、事件生命周期、场外人物投影与结构化输出优势，吸收参考实现的工作流式 Prompt、世界现场推演与 UI 信息层级；优先减少 AI 不需要知道的程序细节与重复结构说明。

## 审计原则

- 模型负责业务判断；Schema 负责结构；validator / normalizer / lifecycle 负责程序约束与存储维护。
- 同一规则只保留一个主来源，避免 DEFAULT_PRESET、CORE_WORLD_RULES、protocol()、Schema 四处重复。
- 世界推演优先维护共享“现场”，人物再在现场中行动；同一群体、资源与环境事实不复制进每个 NPC。
- “身边发展”是程序投影，不是第二套持久数据库。
- MVU `背景故事` 继续表示人物履历，不改名、不拿动态世界关系覆盖；世界引擎另维护低冗余的 `背景关联`。
- 玩家资产与世界资源点分离：资产是玩家拥有并参与建设/战损/产出的玩法实体；资源点是地区中可争夺、利用、耗尽、破坏或控制的世界事实。
- 用户自定义 Prompt 不被内置模板升级覆盖；只自动升级首次安装或当前使用内置默认的配置。

## P0 变更边界

P0 已完成：

1. `DEFAULT_PRESET`：从规则说明书改为明确执行 Pipeline。
2. `CORE_WORLD_RULES`：只保留自定义 Prompt 也不可绕开的业务不变量。
3. `protocol()`：删除与 Canonical Schema 重复的字段清单，仅保留 Schema 无法表达的业务语义。
4. 内置默认 Prompt 文档版本 `8 -> 9`。
5. 新增 `tests/world-engine-prompt-pipeline.cjs`，P0 专项检查通过；旧测试按 main 基线对照，不新增失败。
6. P0 一次性改写脚本与临时 workflow 已删除，不进入正式交付。

P0 明确未修改：MVU 字段、事件生命周期、世界书热人物投影数据结构、NPC 构筑审计、UI 与主题系统。

## P1-A：世界现场与人物背景关联

### 数据归属

- `世界.后台.人物.<人物>.背景关联`：只记录人物与团体/组织/社交圈/阵营等持续世界关系；不复制地点，不复制 `关联事件`。
- `世界.后台.势力地区.<地区>.现场群体`：记录共享现场中的群体，如难民、守军、商队、工人、教团成员。
- `世界.后台.势力地区.<地区>.资源点`：记录地区内可被争夺、利用、耗尽、破坏、控制的地点/设施/自然资源。
- `身边发展`：不持久化。程序按人物地点解析所属地区，并组合同地人物、现场群体、资源点、环境状态形成只读视图。
- `背景故事`：仍属于 MVU 人物履历，不改字段、不由本次 P1-A 迁移。
- `资产`：仍是玩家资产系统；资源点只有在剧情明确获得长期所有权/控制后，才由正常 MVU 流程转化为资产。

### AI 推演顺序

1. 先更新当前区间内发生变化的地区现场：环境、控制、群体、资源点。
2. 再依据人物所属世界、地点、背景关联、关联事件、认知与当地现场决定人物行动。
3. 相同群体/资源只写在地区一次，不复制到每个人物。
4. 人物离开地区后，`身边发展` 会自然随地点重新投影，不需要模型清理人物内的冗余现场资料。

### P1-A 验收

- Canonical Schema 自动包含 `人物.背景关联`、`势力地区.现场群体`、`势力地区.资源点`，不新增另一份顶层资源数据库。
- 旧后台记录经 `normalizeBackendState` 自动补新字段，不要求存档迁移脚本。
- 两名位于同一地区的热人物可以共享同一组现场群体/资源点，但后台只存一份。
- 正文 `世界.场外人物动态` 对热人物可看到精简的背景关联与派生身边发展；非热人物仍不投影。
- 现场群体/资源点不会因为人物移动被复制或删除；人物移动只改变派生视图。
- 活跃异端、事件生命周期、探索/势力结算、MVU `背景故事`、玩家资产系统保持原职责。

## 后续顺序

P1-A 世界现场数据语义 → P1-B 角色管理/UI 视觉重构 → P1-C Prompt 可观测性 → P2 单文件拆分。
