# 世界引擎接入

把 `世界推进系统.js` 作为独立酒馆脚本加载，并更新 `悬浮球状态栏.js`、`ZOD脚本.js`、`辅助计算脚本.js`、结算任务美化，以及世界书的 `[variables]当前变量`、`[mvu_update]变量更新规则` 两个条目。酒馆仍只加载这一份单文件；仓库中的开发源码位于 `script/world-engine-src/`，修改后运行 `python tools/build-world-engine.py` 生成 `世界推进系统.js`。构建不会自动同步到已导入酒馆的角色卡。

终端设置新增「世界推进」总开关，作为独立世界引擎的唯一用户开关。关闭时点击左侧「世界」仍显示原来的 `renderWorldTab` 世界面板，正文/MVU继续使用旧世界推演规则；开启时点击「世界」进入独立世界引擎面板，返回或按 Esc 恢复终端。独立脚本未加载时总开关无法启用，但旧世界面板仍可正常使用。

世界推进支持两套互斥的模型来源。默认关闭「专属 API」时，沿用终端「额外模型配置」，并与商城刷新、血统融合共用连接；开启世界推进时只有这种模式会自动启用终端额外模型。若在世界引擎「设置」中启用「世界推进专属 API」，世界推进只使用自己的地址、Key、模型与预设，主神终端 API 不会被自动开启，也不会在专属 API 配置错误时偷偷回退。专属接口配置仅写 `samsara_world_engine_v1` 的 localStorage，不进入 MVU。总开关已开启但当前选定的 API 通道尚未就绪时，`isEnabled()` 返回 false：自动推进暂停，同时 EJS 恢复旧因果轨道、传闻与正文世界推演。每个正文楼层的 MVU 更新完成后，仅在总开关开启且当前 API 通道 Ready 时执行一次联合请求。每次请求 120 秒超时；失败保留旧状态，可手动重试。

## 开发源码与单文件交付（P2）

世界引擎采用“开发源码分片、运行时单文件”的方式。业务修改应落在 `script/world-engine-src/*.part.js`，不要把 `script/世界推进系统.js` 当作独立第二份源码维护。修改完成后执行 `python tools/build-world-engine.py`；提交前执行 `python tools/build-world-engine.py --check` 与 `node tests/world-engine-modules.cjs`。构建器只做固定顺序拼接，不引入 npm、浏览器模块或额外运行时依赖，因此现有酒馆安装/加载方式不变。


## 2026-09-08 世界引擎界面重构

独立世界引擎的主导航改为顶部模块条，避免继续复刻原主神终端的左侧 Tab 结构。主界面采用“世界推进总览 + 探索与势力 + 角色/任务/传闻等专页”的档案控制台结构。

- 原「势力与地区」统一改名为「探索与势力」，提示词分段也迁移为 `【探索与势力】`；旧 localStorage 中的 `【势力与地区】` 会自动迁移，不产生重复分段。
- 「世界动向」只保留在世界推进总览；探索与势力页不再重复同一批地区/势力变化。
- 世界推进页改为紧凑 dashboard：顶部 4 个摘要指标，中间以世界动向与时间线为主，右侧仅保留下一关键节点、任务简报与最多 4 条重点 NPC 动态。
- 日历不再默认折叠，而是作为时间线固定组成部分直接显示；点击日期继续筛选事件。
- 人物名册与世界推进的人物动态都会过滤当前 SillyTavern 用户名，以及 `{{user}}` / `<user>` /「玩家」别名；玩家自身不再混入后台 NPC 管理。
- 桌面端模块导航改为顶部横向导航；主内容使用“纪事控制台”视觉语言，与原终端保持同世界观但不再沿用原版页面骨架。移动端保持横向可滚动模块条与单列内容。

## 当前实现

### 正文抽取（2026-09-10）

世界推进在读取 AI 楼层后统一清洗原始消息，实际发送的 `正文楼层` 和世界书关键词扫描使用同一份清洗结果。不会修改聊天原文，也不依赖酒馆只影响显示的正则。

- 使用参考助手 `bodyTagsText` 留空的整楼过滤方式：不要求正文格式，也不因出现正文标签而丢弃标签外叙事。先移除排除区块，再剥掉其余 HTML 标签（保留角色占位符 `<user>`）。
- 排除参考助手的思考、`action / summary / update / scene_time`、美化面板及审核块，同时覆盖本卡的 `dm_think / UpdateVariable / JSONPatch / CombatResult / CraftResult / CheckResult / options` 等区块、脚本、技术代码和技术折叠日志。支持属性、大小写与嵌套；未闭合技术块从起始标签起丢弃。
- 读取截至当前楼层的历史消息，排除用户、系统及隐藏楼层，按楼层排序，逐条过滤并丢弃空结果，最后取最近配置数量的非空正文。纯更新楼层再多也不会挤占名额；历史不足时发送实际可用数量，没有可用正文则提示错误，不退回原文。
- 战斗/制作面板之间的叙事保留，面板数值不重复发送，已确认状态仍通过当前变量提供。可在「预览下一次请求 → input → 正文楼层」检查实际发送内容。未加任何标记的分析文字无法可靠自动区分。

正文专项验证：`node tests/world-engine-prose.cjs`。

### 世界引擎设置

世界引擎保留独立「设置」页，但不再维护独立色调。面板直接读取主神终端共享主题键 `samsara_theme_v2`，因此暗夜、绯红、靛蓝、羊皮、樱白、抹茶均跟随状态栏当前选择；旧版世界引擎 `tone` 配置会自动清理。世界引擎仅保留自己的字号设置：默认「标准」为16px级别（正文约14px、辅助字不低于12px），「大字」为18px级别（正文约16px），「特大」为20px级别（正文约17px）；标题、正文、卡片说明、表单、按钮、标签、区域档案都会一起缩放。

「模型接口」区可启用世界推进专属 API。配置结构参考主神终端现有额外模型：`apiUrl / apiKey / model / apiPresets / fetchedModels`，支持保存、应用、删除预设，以及通过 `/v1/models` 加载模型。调用采用 OpenAI-compatible `/v1/chat/completions`；结构化结果按 `json_schema → json_object → plain` 做兼容降级。专属 API 开启后拥有严格优先级：所有世界推进请求只走专属连接，主神终端 `Samsara.terminal.request` 不参与，也不作为失败兜底；关闭专属 API 后才恢复复用主神终端额外模型。

界面第二版采用世界档案布局，不再显示 JSON。世界推进页包含副本日期、累计游玩天数、活跃事件、未来节点、人物动态、近期变化和任务进展。月历以当前副本年月为锚；存在程序内部月长元数据时按该月长渲染，否则按公历展示。可切月、点击有事件的日期筛选时间线，操作不会修改世界时间。事件可按状态或关键词筛选。

人物档案保留行动起止时间、行程、认知来源和登场条件；旧存档中的承诺、待决事项、关系变化字段继续兼容，但当前没有独立调度逻辑，因此不再展示，也不要求模型生成。普通角色的生命周期与关系列表做单向联动：若某角色上一状态仍存在于 `关系列表`、当前状态被明确删除，辅助脚本会同步删除同名（含稳定名归一匹配）的 `世界.后台.人物` 记录，避免其继续进入角色管理和副 API 上下文；从未进入关系列表的纯场外 NPC 不会因此误删。异端采用独立生命周期：雷达中仍为活跃的异端属于强制热人物，每轮世界推进都必须复核并维护地点、目标、行动和当前世界时间的更新时间；雷达状态为死亡时，程序同步退休 `关系列表` 与 `世界.后台.人物`，但保留雷达中的死亡追踪记录，死亡状态不可逆。势力地区继续维护控制权、资源、内部派系及近期变化，并作为共享“世界现场”容器维护 `现场群体` 与 `资源点`。人物后台新增可选 `背景关联`，只记录持续的团体、组织、社交圈或阵营关系，不替代 MVU 的 `背景故事`，也不复制地点与事件。任务不再维护第二套“剧本/阶段”树，而是直接通过事件的关联任务与实际任务状态联动。`最近变化`只保存本轮成功提交产生的新变化，跨轮记录由运行记录与历史锚点承担。

### 世界现场与人物背景关联（2026-09-10）

世界引擎的角色管理从“人物各自追逐目标”扩展为“共享现场先推进，人物再在现场中行动”。持久状态仍只保存事实本身，不为每个 NPC 复制同一批周边资料：

- `世界.后台.人物.<名称>.背景关联` 是可选明细，元素为 `类型 / 名称 / 关系`；用于组织、团体、社交圈、阵营等持续关系。MVU `关系列表.<名称>.背景故事` 仍是人物履历，两者职责不同。
- `世界.后台.势力地区.<名称>.现场群体` 保存共享群体，元素为 `名称 / 规模 / 身份 / 动态`；例如守军、难民、商队、工人等。
- `世界.后台.势力地区.<名称>.资源点` 保存可争夺、利用、耗尽、破坏或控制的世界地点/设施，元素为 `名称 / 类型 / 状态 / 控制方 / 动态`。它不是玩家 `资产`；只有剧情明确取得长期所有权/控制后，才由正常 MVU 流程转成资产。
- `身边发展` 与 `身边人物` 不属于 WorldResult Schema，也不持久化。正文投影按人物地点匹配最具体地区，临时组合地区动态、现场群体、资源点、环境状态及同地区人物；人物移动后视图自然变化，不需要模型清理复制数据。
- 默认提示词从 v9 升到 v10，执行顺序明确为“先更新当前区间内确实变化的地区现场，再决定人物行动”。自定义提示词文档仍不被内置版本强制覆盖。

专项验证：`node tests/world-engine-scene-context.cjs` 与 `node tests/world-engine-prompt-pipeline.cjs`。

`node tests/world-engine-ui.cjs` 使用虚构灰港数据运行本地无头 Edge，检查桌面/手机、日期筛选、人物明细、标签页、空状态及返回行为。截图位于 `tests/artifacts`，只用于验收，不会将示例剧情写入角色卡。

- 世界推进、因果轨道、角色、势力地区、任务联动与信息传播共用一次请求和一个快照，结果包含 JSON Patch 增量操作。
- `世界.后台` 的调度核心是事件、人物行动、势力地区、历史与传播；`剧本`仅为旧存档兼容字段，新推演不再写入或依赖。另存最后处理标识与最近20轮运行说明。
- 事件前因及关联对象必须存在，因果链不允许循环。单个候选片段失败时只拒绝该片段并进入纠错清单；正式 MVU 提交仍保持整轮原子性，任一未解决错误都会阻止本轮写入。
- 兼容投影更新因果轨道、势力、探索、传闻以及既有异端的生死状态；异端身份字段与名单成员仍由主神任务锁定，世界引擎不新增、不改写。变量AI已经建立的关系列表 NPC 可由世界引擎通过 WorldResult.关系 稀疏同步在场、种族、身份、层级、HP、THP、EP、是否队友、好感度、态度；对象不存在时禁止新建。HP=0 可用于已确认剧情死亡并进入既有死亡流程。HP_MAX/EP_MAX、最终属性、状态Buff、血统、技能、装备、道具、奖励和主神任务创建仍由原系统负责。
- 世界推进实际启用时，原模型只处理当前场景事实；后台补场外演进并接管副本初始化后的因果轨道与场外传闻。世界动向直接写入字符串字段 `世界.因果轨道.当前阶段`。正文不读取完整后台，而由程序生成两类临时只读投影：`世界.当前事件` 从进行中的当前事件提取名称、状态、时间、地点、公开征兆、可见影响；`世界.场外人物动态` 从真正热人物提取名称及非空的地点、目标、行动、状态、更新时间、公开动态、背景关联和当前事件关联，并按人物地点临时派生 `身边发展`；身边发展组合匹配地区的现场群体、资源点、环境状态、地区动态与最多4名同地区人物，不写回后台人物；不重复输出“是否异端”，异端身份直接以现有异端雷达名单为准。普通人物只选择与当前地点、当前事件或本轮更新有关的真正热人物（最多8名），仅存在于关系列表不再自动入选；玩家本人和已在场 NPC 不进入场外投影。活跃异端不受普通人物数量上限影响并始终优先保留。副 API 返回后只要聊天、副本和世界时间锚点没有变化，就把世界补丁重基到最新 MVU，保留 HP 等无关并发更新；推进锚点变化才丢弃旧结果。
- 后台提交携带楼层标记，辅助脚本只重算稳定值，不额外推进战斗轮次或扣减状态持续时间。稳定值也在写入前按既有公式计算。
- 正文通过当前变量读取完整 `世界.因果轨道`、只读 `世界.当前事件` 与只读 `世界.场外人物动态`。非战斗状态下，`当前阶段` 提供当前局势，`故事线 / 下一节点` 提供跨章叙事方向，`偏移记录` 保留“为什么已经偏离原轨道”的因果记忆；这些都是只读规划依据。人物动态中的 `目标 / 行动 / 背景关联 / 身边发展` 都是给正文保持人物与世界连续性的规划信息，并不意味着玩家或其他角色已经知道；真正对角色可见的内容仍需服从地点、传播与 `公开动态`。战斗状态仍沿用原规则隐藏因果轨道。`世界.当前事件` 最多6条且空字段会省略；普通场外人物最多8名，所有活跃异端额外保留，人物投影同样省略空字符串与空数组。`世界.后台` 完整对象与程序内部 `世界.历法` 始终剔除。
- 世界书目录合并四类当前有效来源：角色主书、角色附加书、当前聊天绑定书、酒馆全局启用书；同名世界书只加载一次，并在目录中标明来源。可逐条勾选，普通禁用条目可在强制模式显式纳入。`[variables]`、`[mvu_update]`、正文额外思考、选择世界/主神任务/试炼/结算等技术条目始终隔离，避免把 MVU 和正文协议重复塞给世界引擎。正文只读取最近 1—100 个 AI/assistant 正文楼层，默认 6 个；玩家 user 输入不进入世界推进上下文。动态条目仍经 EJS 求值；未绑定且未全局启用的其他世界书不会自动读取。请求总字符超过 24 万会报错，不静默截断。
- 副本时间由正文/MVU原流程维护，后台不改两套时间。普通副本完整结算清空后台；单一世界结算保留。结算楼层不推演，下一个普通正文楼层可继续。
- 切聊天、swipe、删楼取消请求；MVU 楼层快照保存状态。历史面板不触发当前副本清理。进主神空间后停止副本推演。

## 模型补丁容错

世界模型返回的是增量事实，不再要求新建后台记录时一次写齐所有模板字段。对 `/世界/后台/{事件|人物|势力地区|历史|传播}/{名称}` 的整记录补丁，引擎会先用当前模板补缺省字段，再与已有记录合并；因此遗漏 `公开动态`、`关联事件`、`目标` 等空字段不会导致整轮失败。未知顶层字段会被丢弃，可选明细数组（如行程单条记录）的内部结构仍严格校验。

旧存档中的半截后台记录也会在每次事务开始时按当前模板自愈。模型若误写 `/系统状态/待播报记录`、后台运行记录/最近变化/处理标识或旧后台剧本，这些程序自管路径会被忽略而不是让整轮回滚；玩家属性、货币、奖励、世界时间等危险越权路径仍然硬拒绝。

显式旧故事线导入的主线节点现在只作为安全骨架写入，不再要求所有导入节点在同一轮补齐时间与条件。后续滚动时间轴会逐步排程，因此不会再出现“主线节点尚未排程”导致整轮无法落盘。

## 事件分层的程序约束

事件层级不再完全相信模型给出的 `分类`。世界引擎在请求前、补丁应用后和 UI 展示前都会执行确定性归一：

- 合法分类只有 `当前事件 / 近期节点 / 宏观节点`。旧 `近期事件`、空分类和旧 `主线节点` 自动迁移：进行中事件归为当前事件，其余默认归为近期节点。
- 模型即使显式写 `宏观节点`，若事件明显属于房间/楼层/校门/单座桥梁、会合、夺取交通工具、单次突破、搜索调查等局部动作，程序会自动降级为当前事件或近期节点。若降级后待发生宏观节点不足3个，本轮不会写入，而是进入模型纠错重试。
- 程序只处理**明显可判定的局部事件**；篇章转折、据点体系兴亡、战争/政权、战略级灾难、基础设施失效、长期迁移、关键人物命运等语义尺度仍由模型结合原著知识判断。这样避免把所有作品的宏观定义硬编码成一套关键词。
- 因果轨道仍只允许宏观节点投影。有效故事线形成后，后续宏观节点如果缺少直接前因，程序按故事线顺序补上前一个宏观节点，形成最基本的宏观因果链；已有其他前因不会被覆盖。
- 对后台人物，若人物稳定名（或稳定名中点前的明确简称）直接出现在事件文本，或事件 `参与者` 已明确列出该人物，程序会同步 `事件.参与者` 与 `人物.关联事件`。隐含关系仍不猜测，交给模型显式写参与者。
- 时间线 UI 不使用对象插入顺序。固定显示顺序为：进行中的当前内容 → 待发生当前事件 → 近期桥接 → 宏观锚点 → 已完成/已取消；同层再按作品时间排序。界面同时显示事件分类标签，并分成“当前进行 / 近期桥接 / 宏观锚点 / 已结束”组。
- 世界推进面板的“下一宏观节点”与调度器使用同一 `timelineState.下一宏观节点`，不存在 UI 自己猜节点的第二套逻辑。

任务世界中新写入的 `传闻.情报交易` 如果使用“空间币”定价会在程序层拒绝并要求模型纠正为本地货币；主神空间仍允许空间币。旧存档中的历史错误价格不会仅因为存在就阻塞整个世界推进，等该情报被更新/消费时再按新规则处理。

## 宏观推演、因果轨道展开与可选世界书

世界推进的设计目标不是给每一回合增加更多细节，而是补足普通正文推演最容易缺失的**宏观世界演进**。

核心关系：

- `世界.因果轨道.当前阶段`：直接保存一段可读的当前世界局势描述，是世界推进面板“世界动向”和正文背景的唯一持久化来源；仍保持 string，不增加名称/描述子层。
- `世界.因果轨道.故事线 / 下一节点 / 偏移记录`：继续承担宏观未来和偏移账本，并在非战斗正文中作为只读方向/记忆骨架暴露；正文可以用它们维持长期节奏与因果连续性，但不得把它们当成角色已知情报或预知。
- `世界.后台.事件`：因果轨道的展开版。它可以保存更多宏观节点，并在当前时间接近某个节点时，将“当前 → 下一宏观节点”展开成当前事件与近期节点。
- `世界.当前事件`：不是持久变量，而是当前变量脚本从后台事件临时生成的正文安全视图；只投影正在进行的当前事件的 `名称 / 状态 / 时间 / 地点 / 公开征兆 / 可见影响`，没有公开信息的事件、近期节点和未来宏观节点都不进入正文。
- `世界.场外人物动态`：同样不是持久变量，而是从 `世界.后台.人物` 临时生成的热人物视图。字段为 `名称 / 异端 / 地点 / 目标 / 行动 / 状态 / 更新时间 / 公开动态 / 关联事件`；关联事件只保留当前进行中的当前事件，避免未来事件名称泄露。普通冷人物不发送；活跃异端强制发送。
- 异端雷达仍是独立的身份/经历/阵营/职业/层级/生死追踪数据库，正文原本即可读取。世界引擎只允许更新既有异端的生死状态，不允许新增名单或改写身份字段。活跃异端每轮必须有后台人物活动；一旦雷达死亡，或其关系列表实体 HP≤0/明确死亡，辅助脚本把雷达锁为死亡并删除关系实体与后台活动，后续 Compiler 也拒绝为死亡异端重建人物记录。
- 场外人物、势力地区、探索和传播不是独立的第二条故事线，而是解释这段桥接区间内世界如何实际走向下一宏观节点；当前事件负责现实局势，人物动态负责人行动连续性，不再另造一份“正文承接”。

### 宏观知识来源

无限流不能要求每个任务世界都附带校历或剧情年表。宏观推演按以下优先级取事实：

1. 当前变量与正文已经确认的事实；
2. 角色卡/世界书中明确写出的设定、同人差异和时间资料（若存在）；
3. 模型已有的原著/世界知识；
4. 只在前三者不足时做谨慎推断。

因此**没有世界书不是失败条件**。例如进入知名原著世界时，世界引擎应能凭模型已有知识识别后续经典篇章转折、世界级灾难、战争、基础设施失效、关键人物命运或主角团重大迁移，并建立宏观节点；不能因为最近正文只写学校/房间/一场战斗，就把未来宏观层也缩成这些局部动作。

如果存在世界书，世界引擎仍会正常按蓝绿灯读取。时间轴未初始化或待发生宏观节点不足3个时，标题明确属于“校历 / 年表 / 时间线 / 大事记 / 大事件摘要 / 剧情大纲 / 章节控制器”等的已启用条目可临时作为**宏观资料补充**读取；它们用于校正模型知识，而不是宏观推演的前置依赖。宏观节点补足后恢复普通激活规则。

这一点借鉴了 `Draw on/日式中专大乱斗` 的“固定大事件 + 滚动近期日程”结构，但轮回战场不复制其按自然日补事件的校园密度。真正重要的是层级关系，而不是校历本身。

`助手agent_v0.15.js` 的配置说明也强调：本轮首次使用就必须准确知道的信息不应只依赖绿灯关键词。轮回战场进一步把这一原则推广为：**宏观原著知识即使没有专门世界书，也属于世界推进模型应自行利用的知识。**

### 当前 → 下一宏观节点

每次请求的“时间线调度”都会给出：

- 当前时间锚点；
- 下一宏观节点；
- 桥接区间起点/终点；
- 是否缺少宏观骨架；
- 哪些宏观节点已经接近，需要开始展开。

模型首先维护宏观骨架，然后才推演桥接区间。人物行程、势力变化、近期事件和传闻原则上只展开到“下一宏观节点”；更远的内容继续保持宏观摘要，等边界接近后再展开下一段。这样世界引擎不会变成无边界的细节模拟器。

精确日期不确定时允许使用“爆发后数日 / 第X夜 / 某篇章前后”等作品内时间，不得为了填日历虚构公历日期。

世界推进面板中的“下一关键节点”在对应后台事件存在时为可点击项；点击后会定位时间线并滚动高亮对应事件。

## 传闻与情报交易职责

世界引擎实际启用时，场外传闻的**生成、淘汰与传播**由世界引擎维护：

- 后台传播如果 `状态` 明确为结束/停止/失效/过期，或可解析的 `到期时间` 已到，会在下一轮请求前由程序自动回收；副API热上下文最多保留最近24条仍有效传播。
- 非战斗聚集地只有出现新的传播事实时才维护街头巷议，不再无因果地每轮刷新。
- 酒馆、黑市、交易区等真实情报场所可以维护1~2条付费情报，保留原有“卖家 / 情报评级 / 购买前摘要 / 本地货币要价 / AI可见真实内幕”结构；任务世界禁止用空间币定价。
- 主要城镇或新大区域的公告/檄文仍要求真实发布者并关联当前势力。

玩家**当场购买**某条已有情报属于当前场景即时变量行为，因此保留给普通 MVU：世界引擎开启时，MVU 会显示一段最小“即时情报交互”规则，只允许处理正文已经明确完成的购买、支付、remove，并按原规则转化为任务或探索；明确禁止 MVU 自己新增/刷新传闻。这样本地委托仍可走原 `任务.列表` 系统创建，世界引擎只负责其场外事件联动与后续状态同步。

## 因果轨道、EJS职责切换与提示词结构

世界引擎开启时，后台事件图负责场外世界运行，`世界.因果轨道`只作为3~5个宏观节点的投影。若故事线只有一句概括、少于3个节点或超过5个节点，引擎会优先要求模型修复；若模型漏写而现有事件已足够，引擎会按已有事件和世界时间自动补成3~5节点，不凭空制造新事件。玩家或其他人物只有在实质改变关键人物命运、重大事件、势力格局或主线可行性时才新增偏移记录；偏移导致旧主线不可继续时，同步重构故事线与下一节点。完整偏移账本继续留在MVU中参与稳定值计算，但副API只读取最近8条偏移，并额外获得“记录总数 / 隐藏旧记录数 / 累计影响 / 当前稳定”摘要；旧偏移因此不会无限占用AI上下文，也不会因为隐藏而改变稳定值。世界超稳仍禁止新增偏移。

`[mvu_update]变量更新规则` 与 `⚙️额外思考` 不再永久删除原有世界推演能力，而是通过 EJS 检测 `Samsara.worldEngine.isEnabled()`：世界引擎开启时隐藏普通MVU的因果轨道、场外传闻及正文场外推演职责；关闭时恢复原有因果轨道、传闻和 Step.5 世界推演提示。因此关闭独立引擎后，原流程仍可独立工作。

分段提示词现在是完整可编辑工作层：标题与正文都能修改，可新增、删除，并通过上移/下移调整最终 system 顺序。旧 localStorage 预设在首次进入新版编辑器时仍会执行一次结构迁移，补齐当时缺失的必要默认段并把旧 `【势力与地区】` 迁移为 `【探索与势力】`；迁移完成后进入 `presetEditorVersion=2`，之后用户主动删除的分段不会再被自动补回。核心世界约束、WorldResult 协议和安全边界仍独立注入请求，因此自由编辑工作层不会解除程序级调度与写入保护。

## v4 世界动向与正文投影迁移

v4 删除了持久化的 `世界.后台.公开摘要` 与 `世界.后台.正文承接`，避免“当前阶段 / 当前事件 / 摘要 / 承接”多份事实源互相漂移。旧 v3 存档加载时，若存在 `后台.公开摘要`，会把该字符串直接迁移到 `世界.因果轨道.当前阶段`，随后删除旧 `公开摘要` 与 `正文承接`；ZOD 与世界引擎两侧都提供这项迁移，避免加载顺序导致旧摘要丢失。旧模型偶尔返回 `公开摘要` 时，兼容解析层也会把它当作 `因果.当前阶段` 处理，但 v4 Canonical WorldResult Schema 已不再允许这两个字段。

内置世界推进“默认设置”在移除旧摘要/承接结构时升级为 v4；恢复正文读取完整因果轨道时升级为 v5；加入场外人物动态与活跃异端强制活动/死亡防诈尸规则后升级为 v6。仍在使用内置默认的用户会随版本获得最新提示词；个人默认/自定义文档不会被强制覆盖。

## WorldResult 业务层与程序编译

世界推进默认输出协议已从“模型直接生成 JSON Patch”升级为 **WorldResult v1**。

处理链路：

```text
副模型
  ↓
WorldResult（业务事实）
  ↓
World Result Compiler
  - 稳定名称匹配
  - 新增/更新判定
  - JSON Pointer 转义
  - 后台记录默认字段合并
  - 因果轨道故事线投影
  - 显式人物/事件引用同步
  ↓
安全 patches
  ↓
applyPatches / 程序结构修复 / Schema 校验
  ↓
单次 MVU 原子写入
```

模型不再需要知道 `/世界/后台/人物/张彪~1狂暴分支` 这类存储路径，也不再决定 `add/replace` 或 Pointer 转义。旧 `summary + patches` 回复仅保留运行期兼容，不再出现在新提示词中。

WorldResult 使用中文业务字段，核心包括：

- `摘要`；世界动向直接写在 `因果.当前阶段`，不再有 `公开摘要 / 正文承接`
- `事件 / 人物 / 势力地区 / 历史 / 传播`
- `因果.{当前阶段, 宏观顺序, 偏移记录}`
- `势力 / 探索 / 异端`
- `传闻.{街头巷议, 情报交易, 布告与檄文}`
- `关系`

实体使用 `名称` 标识。已有实体只提交变化字段；新增实体提交足以确认该实体的事实字段。程序根据当前存档决定新增还是更新。传播和传闻允许业务操作 `移除`；`撤销本轮` 只用于纠错重试，代表从尚未提交的累计业务结果中撤回该提案，不删除既有存档实体。

### 单一结构来源

WorldResult 的 JSON Schema 与 Compiler 共用当前 `RECORDS / DETAILS / EXISTING` 字段定义生成，减少“提示词允许一种结构、程序却接受另一种结构”的漂移。

世界引擎调用额外 API 时传入：

- `schemaName = samsara_world_result_v1`
- `structured = auto`
- 世界推进专用 `temperature = 0.3`

主神终端按 endpoint + model 缓存结构化能力，并自动尝试：

```text
json_schema
  ↓ 不支持
json_object
  ↓ 不支持
普通 JSON 文本
```

只有服务端明确表现为不支持 `response_format/json_schema/json_object` 时才降级；请求取消、认证、限流等普通错误不会被误认为格式能力问题。

### 分层纠错，不再整份重 roll

现代 WorldResult 回复发生业务验收失败时，采用**分片暂存 + 最终原子提交**。回复会先拆成摘要、货币字段、历法字段，以及事件/人物/势力/探索/传播/传闻等单个业务实体；每个片段先独立编译并在当前存档上试运行。通过的片段进入内存事务，失败片段不进入累计结果，也不会落盘。

例如第一次返回：

```text
人物：卫兵开始巡查        ✅
探索：学校-教室          ❌ 粒度过细
宏观：1 个               ✅ 但整体仍缺2个
```

第二次请求会携带“已接受业务结果”和程序生成的“补充清单”。其中卫兵与第一个宏观节点直接保留；错误探索不会污染累计结果；补充清单会明确要求修正该探索实体、再补至少 2 个待发生宏观节点，并补齐 `因果.宏观顺序`。模型只需返回这些缺失/错误片段，Compiler 再按稳定名称合并。

宏观节点数量、因果投影、到期事件处理等跨模块条件在分片验收后统一检查；即使这些整体条件暂时失败，已经通过的局部片段仍继续保留在内存事务。只有累计 WorldResult 全部通过 Compiler、业务约束和完整 Schema 后才执行一次 MVU 写回，因此不会产生“先写一半、第二次 API 又失败”的半提交状态。

同名实体的纠错结果只覆盖本轮累计结果中的对应字段；若要撤回本轮尚未提交的实体提案，使用 `操作=撤销本轮`。

## 借鉴后台助手的长期推演原则

参考后台世界推进预设后，轮回战场吸收的是推演结构，而不是其具体变量树或时间规则：

- **输入语义归一**：世界书=可选设定资料；正文=已经演出的事实；当前变量=唯一存档基准；程序结构修复=已经确定的机器纠正；WorldResult=唯一业务交付物。
- **生活自足**：场外人物因自己的职责、生计、利益和麻烦行动，不围绕玩家空转。
- **时间真实**：请求中由程序计算“本轮时间容量”。时间未推进只能同步即时事实；数分钟/数小时/半天/数日分别限制后台能完成的事项规模。
- **信息不对称**：没有本人在场、既有认知、传播记录、信使/公告/当面传达，就不能让人物凭空知道消息。
- **各司其职**：事件记录客观局势，人物记录自己的行动和认知，地区记录环境秩序，传播记录消息渠道；不同实体不复制同一整段说明。
- **见面前停步**：场外人物即将进入正文与玩家产生直接交互时，后台推演停在见面前一步，把真正对话/战斗交给正文。
- **不复述正文**：正文已经演出的对白、动作和互动不是新的后台日常事实。

没有照搬的规则包括：世界引擎自行推进世界时间、所有小事件固定2~3轮结束、强制使用现实绝对日期，以及输出显式思考过程。这些与轮回战场的世界时间所有权和多作品时间体系不兼容。

## 事件时间锚点、生命周期、时间硬约束与跨档检查隔离

待发生/进行中的事件不再允许空时间，也不接受单独的“近期 / 稍后 / 未来 / 待定 / 未知”作为时间字段。能确定世界日期时写具体日期/时段；远期宏观节点精确日历未知时，使用可排序、可理解的相对或因果锚点，例如“爆发后数日”“校舍突围战后当日傍晚”。旧存档中已有的空时间/模糊时间会在后续请求中进入“本轮必须补全的事件时间锚点”，同楼层手动修复也允许重新执行。

局部活动不会再因为旧版漏改状态而永久挂在“进行中”。程序按当前世界时间识别陈旧活动：当前事件超过约7个世界日、近期节点超过约30个世界日仍未更新时，会进入“本轮必须复核的超期活动事件”。副模型必须选择结束/取消，或明确确认仍在持续，并把更新时间推进到当前世界时间、更新当前进展并填写下次检查。若本轮确认这类陈旧局部事件其实早已结束，程序会清理人物/地区/传播中的软引用，并在没有活跃后续事件依赖时立即压成历史锚点，不再额外等24小时。

完成/取消事件的冷归档也会先移除已经失效的人物、地区、传播软引用；同样已经结束并进入冷区的旧事件之间不再互相阻止归档。当前因果故事线上的宏观节点仍被保护，不会因普通生命周期清理把宏观骨架拆掉。

新增“时间事实硬约束”：模型本轮新写入的已完成/进行中事件、人物更新时间、势力地区更新时间与已发生近期变化、历史、已经开始的传播，只要能解析出数字世界日期，就不得晚于当前 `世界.时间`。旧存档已经存在的未来污染不会让所有无关更新一起失败，而是进入“本轮必须修复的时间越界记录”，要求副模型定点校正；这用于处理“当前2643年，却把2644年闭关写成已完成”一类跨时序污染。作品使用十二时辰时，调度器识别子丑寅卯辰巳午未申酉戌亥及一至四刻，避免把“当日下午”误判成晚于“酉时二刻”。

界面事件排序先按“进行中 → 当前事件 → 近期节点 → 宏观节点 → 已结束”分层；同层宏观节点优先按因果轨道故事线顺序展示，不再因为日期为空而退化成中文名称排序。世界事件页使用与总览一致的分组时间线。旧记录若暂时仍没有可用时间，界面会优先显示条件触发或前置节点关系，不再直接显示裸“日期未定”或裸“近期”。

“请求检查”只显示当前聊天/存档上下文的运行资料，并以 token 为主要容量单位：带 `≈` 的 `tk` 是本地估算；专属 API 返回 `usage` 时，请求总输入/输出改用服务端实际 token。页面同时显示 system/user/Schema 子项、世界书与正文楼层构成、接口来源、模型、实际结构化模式/降级链、耗时和逐次纠错结果。Schema 是 system 的子项，不与总输入重复相加。CHAT_CHANGED / MESSAGE_SWIPED / MESSAGE_DELETED 会取消旧请求并清空 lastRequest、previewRequest、lastReply、lastWorldResult、编译补丁、失败记录、重试计数与观测记录；这些检查资料从不写入 MVU 或 localStorage。

## 模型回复纠错与失败重试

世界推进的“请求检查”页提供 **失败重试次数**，默认 `3`，可设置 `0~5`。该数字表示：首次副 API 请求已经返回回复，但回复在 JSON 解析、WorldResult 业务校验、Compiler 编译、补丁应用、外部 Schema 校验或宏观骨架验收阶段被拒绝后，最多再请求多少次。重试期间不落盘；只有累计业务结果完整通过后才执行一次 MVU 写回。

现代 WorldResult 回复发生失败时，重试请求会携带：

- 上一次拒绝原因；
- 上一次模型原始回复（最多保留末尾 12000 字）；
- 已经逐片验收通过的累计 WorldResult；
- 程序生成的“补充清单”，例如“探索/学校-教室：粒度过细”“宏观骨架还需补2个待发生节点”“补写因果.宏观顺序”；
- 明确要求严格按补充清单只补充或修正未通过的业务片段，不得重新生成 JSON Pointer、add/replace/remove 路径或整份存储补丁。

已经正确的人物、事件、传播等业务结果会继续保留在内存事务中。同名实体的新回复只覆盖本轮需要修正的字段；若某个尚未提交的业务提案应撤回，使用 `操作=撤销本轮`。Compiler 会在每次验收时基于当前源状态重新编译安全 patches，因此重试不会把旧路径选择或旧 Pointer 缓存在业务层。

以下情况会由程序直接容错，不浪费一次模型重试：

- 结构化提供方把业务对象单层包装成 `WorldResult`、`world_result`、`world_update` 或 `result`；
- Compiler 能确定的名称归一、JSON Pointer 转义、新增/更新判定、后台缺省字段补齐；
- 程序自身负责的事件分类修复、宏观投影和关联同步。

以下情况不会自动重试：请求取消/超时、聊天或副本锚点已经变化、额外 API/ZOD 未配置，以及真正的安全白名单越权（`禁止写入`）。写入调用已经开始后如果失败，会标为“写入未确认”，也不会再次请求模型，避免重复提交。

当请求开始时本就缺少宏观骨架，而累计 WorldResult 经事件层级规范化后仍没有至少 3 个可推进宏观节点（`分类=宏观节点` 且状态为 `进行中/待发生`），本轮会以“宏观事件不足”进入纠错重试；正在进行的阶段级宏观事件本身计入骨架，不再额外强迫再造 3 个未来节点。明显属于会合、撤离、赶路、局部争夺/突破的事件即使模型标成宏观节点，也会先降为当前事件/近期节点后再计数。已经被旧版本标记为“本楼层已处理”的存档，如果仍检测到宏观节点不足或因果轨道不是有效宏观投影，新版本允许在同一楼层执行一次修复。

旧版 `summary + patches` 回复仅保留运行期兼容。其路径归一和安全过滤属于兼容层，不再是新提示词协议，也不应作为新功能继续扩展。

## 运行时容错与并发重基

世界模型可把首次设置写成 `replace`。对于后台事件/人物/势力地区/传播的合法记录和明细字段，目标尚不存在时按安全 upsert 处理；例如 `/世界/后台/事件/校医室聚集/开始时间` 会先建立事件骨架，再写入开始时间。人物稳定名会与后台人物、关系列表和异端雷达做标点归一匹配，因此 `张彪~1狂暴分支` 可自动落到已有的 `张彪·狂暴分支`，避免因斜杠/中点差异创建重复人物。

副 API 请求期间若辅助脚本或其他 MVU 逻辑只改变不相干字段，世界引擎会把补丁重基到最新变量后再提交，不再因为完整 stat_data 不同而整轮失败。只有聊天楼层、世界名称、世界时间或主神空间状态等推进锚点发生变化时才拒绝旧回复。危险越权路径、奖励、玩家属性与玩家持币余额等安全边界仍保持硬拒绝；唯一新增例外是世界经济层的 `世界.货币.体系 / 购买力基准 / 经济波动`，由 WorldResult 按字段增量维护。

## 分层时间轴与归档

世界推进不再把日历当成单纯展示。每次请求都会生成“时间线调度”信息，以 `世界.时间` 为唯一锚点，判断是否缺少时间轴、是否需要补充远期宏观节点、哪些宏观节点已经接近当前时间需要展开，以及哪些非公历/作品内纪年事件需要模型按作品语义复核。

事件按三种尺度组织：当前活动层用于数小时到约两天内的精确节点；近期规划层用于数天到数周的重要人物、势力与局部事件；宏观锚点层用于更远的战争、政权、灾难与原著关键节点。紧凑副本可按小时或“第X夜”推进，大型长期世界只保存必要宏观节点，随着时间接近再滚动展开，避免一次生成多年琐碎日程。

`后台.事件` 现在采用生命周期回收，而不是等堆到约180条才清理。无人物/地区/传播/后续事件引用的“已完成/已取消”事件，在可比较世界时间下结束超过24小时后会压缩为历史锚点；作品内时间无法比较时，最多保留最近8条无引用结束事件。约180条仅保留为异常旧存档的硬兜底。历史锚点在MVU中仍可保留约200条，但副API热上下文默认只读取最近24条，因此冷历史不会长期占用提示词。模型本身仍不能直接删除普通事件或改写历史，清理由引擎在事务内完成。

针对 MVU 的传闻结构错误，世界引擎开启时 `[mvu_update]变量更新规则` 仍会显示 `街头巷议 / 情报交易 / 布告与檄文` 的真实对象结构，但把街头巷议和布告标为精确只读路径；普通变量模型仅在正文已经完成购买时允许移除既有情报交易。世界引擎开启时也不再注入“传闻为空就补2条”的普通 MVU 规则，避免与独立世界引擎职责冲突。完整 `[mvu_update]` 条目仍属于技术条目，不直接塞进副 API 的世界书上下文；后台模型继续以 Canonical WorldResult Schema 为唯一写入结构。

`世界.货币` 现在同样按职责切换：世界引擎开启时，普通 MVU 把 `/世界/货币` 列为只读并隐藏可写货币规则；世界引擎关闭时恢复原货币更新规则。副 API 的 Canonical WorldResult 新增可选 `货币` 对象，只允许 `体系 / 购买力基准 / 经济波动` 三字段，并按叶子字段增量写回，禁止触碰玩家持币余额或奖励。

`世界.探索` 与 `世界.势力` 也改为同一职责模式：世界引擎开启时普通 MVU 不再得到其可写结构，只把 `/世界/探索`、`/世界/势力` 视为只读结算台账。世界引擎的固定核心规则完整继承原变量规则的探索/声望约束，因为两者会直接进入空间币结算：探索只允许整体地标，天台、教室、走廊、楼梯、单个房间等微观区位不得独立计探索度；后台 NPC 的发现不得算给玩家；探索度按 0/10/30/60/90/100 阶段理解且不得无因回退。势力声望只反映该势力对玩家的真实关系结果，不等于势力自身兴衰，维持 -5000/-1000/0/500/2000/5000/10000 锚点、单轮绝对变化≤1000、超过500仅限重大核心事件、同一事件只结算一次。程序还会拒绝新产生的微观探索项，并在下一次世界推进时把旧版 `主区域-天台` 一类记录合并回主区域，避免重复领取探索收益。

货币体系不是初始化后锁死。世界引擎可在战争、末日、政权崩溃、流通网络断裂等实际事件使旧货币失效时，把 `世界.货币.体系` 改为当前真实交易媒介（例如以物易物、粮食、药品、弹药或新票据），并同步购买力基准与经济波动；仍禁止把任务世界经济改成空间币体系。

`世界.历法 = {名称, 月份天数, 闰年规则}` 现在是纯程序内部元数据：由世界引擎维护，但 `[variables]当前变量` 会在输出前强制删除它，`[mvu_update]变量更新规则` 也完全不提及该字段，因此正文 AI 与普通变量 AI 都不知道它存在。普通 AI 仍只按剧情经过时间更新 `世界.时间`；ZOD 在写入后使用隐藏月长做最终归正，例如内部规则声明二月28天而 AI 写成 `02月31日`，会自动进位为 `03月03日`。世界引擎自身也拒绝违反内部月长的事件日期。日历面板使用同一内部月长渲染，自定义28天月份不会显示第29~31日；无内部月长时数字年份按正常公历，无法识别作品年份但能识别月日时继续以2026作为仅供 UI 显示的年份。

离线运行 `node tests/world-engine.cjs`。酒馆验收还应检查真实副 API 返回、EJS 世界书读取、两脚本加载顺序、移动端面板、普通/单一世界结算以及重生成后的楼层恢复。没有真实 API 或酒馆运行证据时，不能把离线测试当成实机通过。

### 2026-09-09 可读性修复

字体大小设置改为统一字号令牌，覆盖主内容、卡片、说明文字、表单与导航，不再出现只放大少数继承字号控件的情况。暗色主题提高次要文字对比度；探索「区域档案」说明框改为跟随主题的深色说明面，不再保留旧白底灰字。羊皮主题顶部导航改为浅色文字/深棕底，并为选中项使用高对比金色按钮，避免棕字叠棕底。


### NPC 构筑审计

角色管理会对“本轮热人物”中的既有关系列表 NPC 做构筑审计。热度只来自当前在场、当前/近期事件参与、活跃异端、当前地点关联或本轮人物动态更新；不会因为 NPC 只是存在于关系列表或层级较高就把多年冷人物重新塞回请求。

审计复用现有《NPC建档与生成规则》《实体生成规则》的核心约束，但不重新默认勾选这两条世界书。请求只对最多 4 个真正需要补强的 NPC 附带完整构筑资料（保留原始属性，移除最终属性/真属性/强化缓存），并列出组件数量、档案缺口以及攻防/机动/Boss阶段机制缺口。

世界模型仍通过既有 `WorldResult.关系` 更新 NPC，不新增顶层格式；可对审计对象补职业、状态、血统、装备、技能、形态库、当前形态和缺失档案字段。动态组件 map 与原数据合并，不覆盖未提交的旧组件；模型不得新建关系列表人物、修改 HP_MAX/EP_MAX、最终属性或真属性。组件变更后程序清空对应真属性缓存，由现有辅助计算流程重新计算。难度辅助脚本继续只负责已有组件的品质强化，构筑审计负责“补缺”，两者职责分离。


### 请求透明度与世界书发送边界（2026-09-10）

提示词工作台把最终 system 分成两层展示：可编辑工作分段，以及程序固定/条件注入的核心约束与 NPC 构筑审计。默认工作层已经有 `【执行流程】`，因此不再追加第二份 `【本轮执行顺序】`。WorldResult 协议说明仍可编辑，Canonical Schema 固定只读。

请求检查中的“本轮实际读取资料”只列真正进入请求的世界书；未勾选或未命中的候选不会显示在实际发送清单。世界书经过激活判定和 EJS 处理后，发送给 AI 的 `user.世界书` 只保留内容字符串，书名、条目 ID 和来源信息只用于本地目录/检查界面。`system · 实际发送原文` 与 `user · 实际发送原文` 分别对应最终提交给模型的 system/user 消息内容。
